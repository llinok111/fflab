# 设计取舍与实测记录

> 本文只记录**做过验证**的结论。未验证的猜测不写入。

## 1. 为什么把"验证"放在产品中心

多数 ffmpeg 教程止步于"命令跑通了"。但这里的真实失败模式是**静默错误**：

| 现象 | 命令退出码 | 日志有无警告 | 实际后果 |
| --- | --- | --- | --- |
| `amix` 未加 `normalize=0` | 0 | 无 | 主轨 -6dB |
| `-shortest` 用在短音轨上 | 0 | 无 | 画面被截断 3 秒 |
| 漏写 `-map` | 0 | 无 | 音轨或视频轨凭空消失 |

退出码为 0、日志干净、结果错——所以判分必须落在**产物测量**上，而不是命令是否成功。

## 2. 判分的两层结构

```
命令形态层  must_match / must_not_match  →  证明"用了正确的手段"
产物测量层  probe / volumedetect / ebur128 →  证明"拿到了正确的结果"
```

两层都与/运算。设计理由：只查命令形态可以背答案；只查产物可以凑巧通过。

## 3. 测量实现的选择

### 3.1 无 ffprobe

本机 `ffmpeg.exe` 存在、`ffprobe.exe` 缺失（`find /c/Users/15082 -maxdepth 4 -iname "ffprobe*.exe"` 零结果）。
替代方案与代价：

| 需求 | 采用做法 | 代价 |
| --- | --- | --- |
| 时长/codec/分辨率/采样率 | 解析 `ffmpeg -i` 输入转储 | 依赖日志格式，需自维护正则 |
| 帧数 | `-progress pipe:1` 的 `frame=` | 需额外一次解码（素材小，可接受） |
| 响度 | `ebur128=framelog=quiet` 的 `I:` 值 | 需 `-nostats` 抑制刷屏 |
| 峰值/均值 | `volumedetect` 的 `max_volume`/`mean_volume` | 同上 |
| 帧级内容指纹 | `-f framemd5` | 解码全片 |

### 3.2 像素格式解析的坑（已修）

`Video: h264 (High) (avc1 / 0x31637661), yuv420p(progressive), 640x360 [SAR 1:1 ...]`

初次实现按"分辨率位置"反查像素格式，抓到的是码率数字（实测 `954`、`3328`）。
正确做法：取 `Video:` 行按逗号切分后的第 2 段。修复后实测 `yuv420p`。

## 4. 帧数偏差：实测记录，不臆断成因

`clip_beta`（3.00s / 25fps / 75 帧）重采样到 30fps，输出随滤镜顺序变化：

| 写法 | fps 滤镜日志 | 输出帧数 | 输出时长 |
| --- | --- | --- | --- |
| `fps=30` | 75 in, 90 out; 0 dropped, 15 duplicated | 90 | 3.00s |
| `fps=30,scale=640:360` | — | 90 | 3.00s |
| `scale=640:360,fps=30` | 75 in, **89 out; 1 dropped**, 15 duplicated | **89** | **2.97s** |

- 三次独立重跑结果完全一致，属确定性行为，不是随机抖动。
- `crop=1280:720,fps=30`、`null,fps=30`、`format=yuv420p,fps=30` 均为 90 帧；
  仅 `scale` 在 `fps` 之前时出现 89 帧。
- **成因未做源码级验证，故本文不下结论。** 教程按实测值设计断言（209 帧 / 6.97s）。

这条也解释了为什么本项目的断言用区间而不是"理论值"：理论值会把人判错。

## 5. 断言语义的两处修正（都由实测推翻初稿）

| 初稿 | 实测 | 修正 |
| --- | --- | --- |
| 第 4 步允许 `-map 1:a:0 -shortest` | 成片变 4.0s，画面丢 3s | 强制 `apad` + 断言时长 6.8–7.2s |
| 第 5 步峰值 `[-3.0, +0.5]` | loudnorm 后实测 -8.2dB，被误判失败 | 改为 `≤ -1.5`（TP 是上限约束，不是目标值） |

## 6. 隔离设计的三道闸

1. **argv 守卫**（执行前）：路径解析后必须在 `workspace/` 内；`assets/` 只读；拒绝协议式输入与 `movie=`。
2. **无 shell**（执行中）：`subprocess.run(argv_list)`，不经 shell；显式拒绝 `; && || | > <` 等元字符。
3. **指纹复核**（执行后）：素材 sha256 前缀比对，发现改写/删除即抛错。

第 3 道是必要的：`concat` 协议可以通过列表文件间接访问路径，argv 层看不全。

## 7. 界面上的两个真实缺陷（靠 CDP 点击才发现）

1. **通过后不前进**：第 1 步通过后仍停留在第 1 步，下一步命令在旧步断言下被判失败。
   → 增加"进入下一步"按钮（**不自动跳转**，否则会冲掉刚生成的断言表格）。
2. **进度条卡在 80%**：最后一步通过后主区未重绘，百分比停留在旧值。
   → 通过后同步更新 `.meta` 数字与 `.bar` 宽度，并在全部完成时插入横幅。

这两个问题都无法通过"接口返回 200"发现，必须真实点击。

## 8. 测试自身的两个坑（已修）

1. **沙箱目录复用**：`TestServer` 多个用例原用同一目录，进度文件跨用例残留，
   导致 `next_step` 断言失败。改用测试方法名作目录后缀。
   （`getattr(self, "_seq", 0)` 无效——unittest 每个用例都是新实例。）
2. **按钮竞态**：断言表格先渲染，"进入下一步"按钮在 `/api/state` 往返后才插入。
   测试若立即查询会误判为"按钮不存在"。改为轮询等待（上限 15s）。

## 9. 视觉证据策略

本机读图链确认不可用（`ViewImage` 返回"所选模型无法接收图像"）。因此：

- **程序化证据**：CDP 断言 DOM 结构、点击、文本内容、几何重叠、横向溢出。
- **像素证据**：`tools/png_stats.py` 自写 PNG 解码（zlib + 五种行反滤波），
  统计尺寸/去重色数/平均亮度/横向分带标准差。
- **验证器自检**：用纯黑、纯白、单色图做反例，确认三条阈值都能判 FAIL。

不把"截图文件存在"当作视觉验收。

## 10. 不做什么

- 不做模拟器：所有断言都来自真实 `ffmpeg` 进程。
- 不内置二进制：不打包 ffmpeg，避免卷入 GPL 分发义务。
- 不做多用户/鉴权：本地单用户工具，绑定 `127.0.0.1`。
- 不承诺跨平台一致：测量阈值在 Windows + ffmpeg 7.1 上标定；Linux/macOS 的
  编码器版本差异可能影响帧数与响度小数位，需重跑 `demo` 复核。
